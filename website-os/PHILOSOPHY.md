# Philosophy

## The OS is a process layer

A reusable design OS should improve reasoning, exploration, implementation, and verification. It should not decide the visual identity of every future website.

The active project provides:

- audience;
- business objective;
- content;
- proof;
- brand;
- references;
- desired emotion;
- functional requirements;
- constraints.

The OS provides:

- a way to discover options;
- a way to select an art direction;
- a way to use tools intentionally;
- a way to implement and test;
- a way to learn from completed work.

## No universal aesthetic

None of these is always good or always bad:

- gradients;
- minimalism;
- glass;
- brutalism;
- rounded cards;
- sharp industrial geometry;
- dark themes;
- light editorial themes;
- shaders;
- 3D;
- video;
- large typography;
- dense interfaces;
- subtle motion;
- theatrical motion.

The relevant question is whether a treatment serves the project's identity, usability, content, and performance needs.

## Visual evidence outranks written rationale

An agent can produce a sophisticated design explanation for an ordinary page. Rendered prototypes and screenshots expose whether the idea works.

## Libraries are ingredients

shadcn, 21st, Magic UI, React Bits, Motion, GSAP, Anime.js, Three.js, and generated imagery can increase the available design vocabulary. They do not replace art direction.

## The first draft is not the finish

The workflow expects browser critique and correction. Quality comes from selection and iteration, not merely a longer first prompt.
