# What We Learned from the First Website OS

The first system improved planning and technical completeness, but it unintentionally narrowed the design space.

## Failure modes

- Too many always-on prohibitions made restraint feel safer than expression.
- Written art direction substituted for rendered visual exploration.
- Requirements were translated literally into separate sections.
- Internal truthfulness constraints leaked into public marketing copy.
- Component MCPs were available but not actively researched or previewed.
- Missing real assets led to synthetic CSS interfaces being treated as portfolio proof.
- Technical QA and visual desirability were blended together.
- One visual motif was repeated until it became the entire identity.
- Utility icon consistency was confused with brand storytelling.

## Changes in this edition

- The active project prompt is explicitly authoritative.
- Only two concise Rules are always on.
- No universal style bans or defaults.
- Visual exploration is rendered, not merely described.
- Directed, explore, and autonomous modes support different levels of manual involvement.
- Component research is a separate optional Skill.
- Motion technology is routed by need.
- Visual assets and real evidence are handled explicitly.
- Browser critique is separate from technical QA.
- Reusable components are extracted only after successful real projects.
