# Promote Pattern

Do not create a universal component library from speculative designs.

A pattern may be promoted after it has:

- solved a real project need;
- survived responsive and accessibility review;
- handled real content variation;
- passed browser and performance checks;
- demonstrated reuse value beyond one brand.

Before promotion:

- separate brand-specific styling from behavior;
- document required dependencies and assets;
- provide meaningful variants and states;
- preserve distinctive behavior without imposing one aesthetic;
- add examples and tests;
- choose a private registry or shared package location.

The reusable asset should expose design controls rather than freezing the original project's visual identity.
