# Acceptance Criteria

## Strategy and content

- [ ] A first-time visitor can identify the audience, outcome, differentiator, and primary action from the first viewport.
- [ ] No unverified claims, invented proof, or placeholder content remains.
- [ ] Functional/data-powered behavior is visible and explained.

## Product and data

- [ ] Primary flow works from input/action to useful result.
- [ ] Loading, empty, validation, success, error, and retry states exist where applicable.
- [ ] External data is validated and credentials remain server-side.
- [ ] Freshness and fallback behavior match the specification.

## Visual and responsive

- [ ] The page follows the approved visual direction and avoids repetitive generic section patterns.
- [ ] Phone, tablet, and desktop layouts have been visually inspected.
- [ ] Text, controls, imagery, and motion remain usable at narrow widths.

## Accessibility

- [ ] Keyboard navigation and visible focus work.
- [ ] Forms have labels and associated errors.
- [ ] Semantic structure, alternative text, contrast, and reduced motion pass review.

## Runtime and engineering

- [ ] No unexpected console errors or failed network calls.
- [ ] Lint, typecheck, tests, and build pass where configured.
- [ ] Material assumptions and limitations are documented.
