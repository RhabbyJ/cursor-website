# Visual reset of the current Operator site

The current site is functionally useful but visually too austere, boxed, technical-manual-like, and obviously agent-generated. Do not polish the current “Field Manual” direction. Preserve working application behavior, forms, truthful content, accessibility, and tests, but restart visual direction through Website OS v2.

## Target

- archetype: premium creative software studio / portfolio
- design ambition: 9/10
- visual impact: grand, refined, memorable, and brand-specific
- strong typography, depth, richer imagery, beautiful icon/illustration treatment, and purposeful high-quality motion
- one signature hero experience and two supporting interactions

The final result must not resemble documentation, an admin dashboard, a stack of bordered data panels, or a default dark developer portfolio.

## Required process

1. Create a Git branch/checkpoint and preserve the current deployment as baseline.
2. Archive the old visual-direction and component-decision documents.
3. Run `/tool-preflight` and prove access to shadcn, 21st.dev, Motion UI/AI Kit, React Bits registry/skill, Browser, Design Mode, and image generation where available.
4. Run `/asset-inventory`. Search the repository for real HarnessMate, hospitality, MyBird, founder, logo, and brand assets. Record missing items.
5. Use `/component-scout` to search—not blindly install—high-quality hero, project-showcase, navigation, and signature-motion candidates.
6. Create three runnable visual routes. They must be materially different and may use expressive techniques such as:
   - cinematic product framing and spatial depth;
   - kinetic editorial typography and rich project imagery;
   - controlled generative/shader treatment with clean premium surfaces.
   These are categories, not mandatory recipes.
7. Each route must include the actual hero copy, one featured-project slice, mobile composition, and a working signature effect.
8. Present screenshots or routes before continuing. Do not build the full redesign until a route is selected or independently wins the visual judge.
9. Polish the selected hero and proof slice until the visual score is at least 8.0 with no category below 7.
10. Build the rest of the page from the selected language. Do not revert to border boxes and data rails as the universal grammar.
11. Use real product evidence. Clearly label temporary asset slots; do not fabricate product UI as proof.
12. Run editorial subtraction, motion composition, final visual judge, and technical QA.

## Specific corrections

- Replace the founder “Photo” placeholder with a real asset slot that blocks launch rather than looking finished.
- Use Phosphor only for utility icons. Create bespoke project diagrams, marks, or illustrations for major visual storytelling.
- Do not reuse one layout primitive across hero, process, differentiator, and case studies.
- Avoid long explanatory paragraphs in the hero and proof sections.
- Do not mark visual acceptance complete while real project assets are absent.
- Fill the visual scorecard with screenshot evidence; a blank scorecard is a failed gate.
