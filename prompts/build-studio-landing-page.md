# Build the studio landing page — Website OS v2

Build a new landing page for an AI-enabled website and software studio.

## Positioning

The studio does not merely build pages. It builds websites connected to the data, workflows, and software behind a business.

Examples of real work:

- HarnessMate — an engineering software product for connector search, mate finding, technical data, and guided engineering workflows.
- Hospitality websites powered by Google Sheets so staff can update menus, events, specials, pricing, and hours without editing code.
- MyBird Real Estate — a custom property-discovery and lead-workflow experience.

Primary conversion: start a project or request a consultation.

Core idea: **Your website should run your business, not just describe it.**

## Quality target

- archetype: creative software studio / portfolio
- design ambition: 9/10
- result: grand, polished, visually memorable, and clearly custom
- not: an engineering manual, admin dashboard, default shadcn page, generic dark SaaS template, or a long essay

Use Phosphor for utility controls, but allow custom SVG, generated art, rich type, depth, shader/WebGL, 3D, photography, and selected animated components when they serve the chosen route.

## Required workflow

1. Read Website OS v2 rules and skills.
2. Create the experience brief and quality profile.
3. Run `/tool-preflight`; prove which MCPs/catalogues work.
4. Run `/asset-inventory`; do not fabricate project screenshots.
5. Run `/visual-exploration` and create three runnable routes. Each must include the hero, navigation, one featured-work slice, and a signature visual experience at mobile and desktop.
6. Use 21st.dev plus at least one of Motion UI/Motion examples or React Bits when available. Search and document candidates; installation remains selective.
7. Stop before the full page and present the three visual routes for selection. When autonomous selection is explicitly authorized, use the visual judge and document the winner.
8. Polish the selected hero/proof slice until it passes the visual gate.
9. Only then build the full landing page.
10. Run the editorial pass, motion composition, blind visual judge, and technical browser QA.

## Content structure

The final page should communicate, not mechanically mirror, these ideas:

- clear hero and CTA;
- three engagement levels: premium website, connected operational website, custom software;
- HarnessMate flagship proof;
- interactive Sheets-to-live-site demonstration;
- MyBird proof;
- a concise process;
- founder trust;
- consultation.

Combine or reorder ideas for the strongest narrative. Do not turn every item into a separate card section.

## Evidence

Use real project screenshots and recordings when available. Until supplied, show clearly labeled asset slots in case-study areas; generated brand art may support the composition but cannot impersonate completed product work.

Do not publish internal guardrails, anti-hallucination notes, or implementation policies as marketing copy.
